# Локализация PzKpfw

PzKpfw использует независимые JSON-пакеты языков. Для добавления языка не требуется изменять Python-код приложения.

## Структура пакета

Каждый язык — отдельная папка с кодом локали:

```text
locales/
  de/
    language.json
    messages.json
  pt_BR/
    language.json
    messages.json
```

`language.json` описывает язык и формат пакета:

```json
{
  "format_version": 1,
  "locale": "pt_BR",
  "native_name": "Português (Brasil)",
  "english_name": "Portuguese (Brazil)",
  "direction": "ltr",
  "author": "Имя переводчика"
}
```

Допустимые значения `direction`: `ltr` и `rtl`. Имена локалей должны совпадать с именем папки. Для обычного португальского используйте `pt`, для бразильского — `pt_BR`.

`messages.json` — словарь исходной русской строки и её перевода:

```json
{
  "Файл": "File",
  "Сохранить": "Save",
  "Новый проект…": "New project…"
}
```

Пустая строка означает «не переведено»: приложение покажет исходный русский текст. Это сделано намеренно — неполный пакет не ломает интерфейс и не скрывает важную команду.

## Создание нового языка

Из корня репозитория выполните:

```bash
python tools/manage_locales.py create --locale pt_BR --native-name "Português (Brasil)" --english-name "Portuguese (Brazil)" --direction ltr
```

Команда создаст `src/is2_re/locales/pt_BR/` и заполнит `messages.json` всеми исходными строками в виде пустых значений. Переводчик редактирует только JSON-файл.

Для установки пользовательского языка без изменения папки программы:

```bash
python tools/manage_locales.py create --locale pt_BR --native-name "Português (Brasil)" --english-name "Portuguese (Brazil)" --user
```

Без командной строки можно открыть **Вид → Язык интерфейса → Открыть папку языков…**, скопировать находящуюся там папку `_template`, переименовать копию в код языка (например, `pt_BR`) и изменить в `language.json` поле `locale`, названия языка и направление письма. Затем заполнить `messages.json` и нажать **Обновить список языков**. Если пакет корректен, он появится в списке; для применения выбранного языка потребуется перезапуск. Папки, имена которых начинаются с `_`, загрузчик игнорирует.

Пользовательские пакеты хранятся в:

- Windows: `%APPDATA%\PzKpfw\locales\<locale>`;
- Linux: `$XDG_CONFIG_HOME/PzKpfw/locales/<locale>` или `~/.config/PzKpfw/locales/<locale>`.

Пользовательский пакет с тем же кодом локали имеет приоритет над встроенным. Поэтому можно исправить встроенный перевод, не меняя файлы программы.

## Проверка и статистика

```bash
python tools/manage_locales.py validate src/is2_re/locales/pt_BR
python tools/manage_locales.py list
```

Проверка контролирует структуру файлов, версию схемы, направление письма и плейсхолдеры. Непереведённые сообщения перечисляются отдельно; это предупреждение, а не препятствие для запуска. В интерфейсе и в каталоге отсутствующие переводы автоматически заменяются исходным русским текстом.

## Правила перевода

1. Не изменяйте ключи слева от двоеточия. Это исходные фразы, по которым код находит перевод.
2. Переводите значение справа. Сохраняйте горячие клавиши (`Ctrl+S`, `F1`), обозначения (`IS-2`, `AElement`, `ConceptModel`, `SPZ`, `XML`) и специальные символы там, где они имеют технический смысл.
3. Не переводите XML-теги, атрибуты, идентификаторы, коды, значения пользовательских проектов и содержимое `.is2`.
4. Старайтесь сохранять смысл предупреждений об экспериментальных алгоритмах и неподтверждённой совместимости. Это технические оговорки, а не декоративный текст.
5. Не добавляйте HTML или форматирование в перевод, если его нет в исходной строке.
6. При переводе на RTL-язык укажите `"direction": "rtl"`. Сейчас приложение включает базовое выравнивание текста вправо, но Tkinter не предоставляет полноценного управления BiDi-разметкой всего окна. Смешанные фрагменты латиницы, цифр и иврита необходимо проверять отдельно на целевых ОС.

## Применение языка

Выбор доступен в меню **Вид → Язык интерфейса**. Выбор сохраняется в пользовательском `appearance.json`. Из-за того, что некоторые подписи форм и справочников создаются при импорте модулей, для полного применения языка программа предлагает перезапуск. Перезапуск не меняет содержимое `.is2`.

## Область покрытия

Встроенный шаблон содержит **1107 исходные строки**. Все восемь дополнительных пакетов заполнены по всему текущему шаблону; плейсхолдеры проверяются автоматически. Это означает 100% заполнение каталога, но не заменяет редакторскую вычитку: переводы остаются начальными версиями, и перед публичным релизом желательно проверить терминологию и естественность формулировок носителями языка.

Процент относится к строкам каталога, а не к переводу пользовательских данных, имён элементов `.is2`, идентификаторов XML, технических кодов или внешнего содержимого, которое приложение не контролирует. Эти значения намеренно не переводятся. Для иврита задано направление RTL, но Tkinter не обеспечивает полноценную BiDi-компоновку каждого смешанного текста; это необходимо проверять в целевой ОС.

`ru_pre1918` — отдельный редакторский пакет дореформенной орфографии, а не автоматическая замена букв во всех пользовательских данных. Для него применяются исторические написания ятя, десятеричного i и конечного ера там, где это подтверждается правилами; отдельные технические названия могут сохранять современную форму. Пакет нуждается в дополнительной филологической вычитке.
