# Публикация PzKpfw 9.9.1

1. Откройте актуальный клон репозитория на нужной ветке. Проверьте `git status`: сохраните или закоммитьте свои незавершённые изменения перед заменой файлов.
2. Распакуйте архив исходников и скопируйте **его содержимое** в корень репозитория с заменой файлов. Папка `.github` тоже нужна: в ней находятся сценарии проверок и сборки.
3. Выполните `git status` и просмотрите изменения. Наложение архива не удаляет старые файлы репозитория. В частности, старый `PzKpfw.exe`, старый wheel в `dist` и ранее отслеженные `__pycache__` могут остаться в Git: `.gitignore` не удаляет уже отслеженные файлы. Проверьте их назначение и удаляйте из Git только те, которые действительно больше не нужны. Другие старые файлы могут содержать историю, образцы или рабочие материалы — не удаляйте их автоматически.
4. Убедитесь, что в изменениях нет личных `.is2`-проектов, временных файлов, окружений Python или результатов сборки. Выполните локальные тесты по README. Добавьте выбранные изменения в коммит и отправьте на GitHub.
5. Проверьте `Source checks` в GitHub Actions. Для получения сборки Windows вручную запустите workflow `Windows application build`; после успешного завершения скачайте артефакт `PzKpfw-Windows`. Сохраняйте EXE вместе с `_internal`.
6. После проверки создайте тег `v9.9.1` и GitHub Release. Текст для описания — в `RELEASE_NOTES_9.9.1.md`. Прикрепляйте EXE только после успешной сборки и проверки на Windows.

В этом архиве — исходный код, а не готовый Windows EXE. Его нельзя проверить на Windows только по результатам локальных тестов без графического интерфейса.
