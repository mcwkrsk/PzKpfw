# Производительность

В интерфейсе частые события изменения размера объединяются: перерисовка схемы и разделителей таблиц планируется не чаще одного раза примерно за 40 мс, а последнее изменение сохраняется. Вычисления и обновление элементов Tk по-прежнему выполняются в главном потоке. При изменении проекта схема строится из текущих данных; долгоживущий кэш проекта не добавлен.

Устранены повторные обходы связей для действий без потомков; в пределах одного построения повторно используются полученные порядки ветвей и атрибуты действий. Отображение связей, форм и матрицы не менялось намеренно.

## Оптимизация интерфейса (ноябрь 2026)

Функции и вид не менялись; ускорены повторные вычисления и перерисовки.

- **Выделение блока на схеме СПД.** Раньше каждый щелчок заново строил сцену и перерисовывал весь холст. Теперь перекрашиваются только рамки прежнего и нового блока; цвета берутся из тех же функций `_course_node_style` / `_is2_node_style`, что и при полной отрисовке. Если холст показывает не текущую сцену, выполняется полная перерисовка, как раньше.
- **Сцена СПД кэшируется** по документу, ревизии правок (`_doc_revision`, увеличивается в `_mark_dirty` и при отмене/повторе), фокусу, глубине и виду. Масштаб, изменение размера окна, тема и выделение сцену не пересобирают. `course_panel.refresh()` и `refresh_all()` сбрасывают кэш.
- **Подписи блоков**: ширина текста кэшируется по шрифту (`_cached_measure`), а длина строки подбирается двоичным поиском вместо замера каждого префикса; высота строки шрифта запрашивается один раз за отрисовку.
- **Связи документа**: внутри `ProjectDocument.read_snapshot()` связи сгруппированы по типу и родителю, а `sibling_order()` вычисляется один раз на родителя. Построения дерева, сцен, декомпозиции, форм и матрицы помечены `@reads_document` и выполняются внутри такого блока. Документ внутри блока не изменяется.
- **Состояние редактора (sidecar)** при выделении и смене вкладки записывается один раз после паузы 400 мс, а не при каждом щелчке. Перед открытием или созданием другого проекта, восстановлением копии и выходом ожидающая запись выполняется сразу.
- **Скрытые представления**: матрица в `refresh_all()` пересчитывается, только если её вкладка открыта (при открытии вкладка обновляется сама, как и раньше). Схемы СПД и декомпозиции, изменённые в скрытом состоянии, рисуются при показе (`<Map>`).
- **Граф связей**: отчёт `build_relationship_graph` переиспользуется до следующей правки, подписи узлов кэшируются, поэтому перетаскивание узла легче.
- Поиск по дереву СПД фильтрует один раз после короткой паузы при наборе; `xml.sax.saxutils` загружается при первом экспорте, а не при запуске.

Замер на проекте из 121 действия и 86 параметров (Linux, Xvfb; на Windows цифры будут другими):

| Операция | Было | Стало |
|---|---|---|
| Выделение блока | ~53 мс | ~2–3 мс |
| Шаг масштаба, вид ИС-2 | ~250 мс | ~39 мс |
| Шаг масштаба, обычный вид | ~53 мс | ~25 мс |
| Правка + обновление всех вкладок | ~100 мс | ~34 мс |
| Отмена / повтор | ~110 мс | ~33 мс |
| Открытие проекта | ~300 мс | ~140 мс |
| Кадр перетаскивания в графе | ~44 мс | ~28 мс |

Совпадение результатов проверено: 663 расчётных представления (дерево, сцены СПД и ИС-2, декомпозиция, SVG, формы, матрица, граф, экспорт) на 7 проектах, включая повреждённый, совпали с прежней версией; быстрое перекрашивание выделения совпало с полной перерисовкой по всем элементам холста. Регрессионные тесты: `tests/test_view_caches.py`.

## Как измерить

Из корня проекта на Linux/macOS: `PYTHONPATH=src python3 tools/benchmark_performance.py`. На Windows: `set PYTHONPATH=%CD%\src`, затем `py -3 tools/benchmark_performance.py`. Сценарий создаёт искусственный проект с 261 действием и 40 параметрами, повторяет измерения и проверяет, что вычисление представлений не изменило проект. Он измеряет только расчёты Python, без графического окна и без замера FPS.

При локальном сравнении старой и новой версии на таком проекте один вызов построения примитивов декомпозиции занял соответственно 102 и 2,8 мс, матрицы — 58 и 12,8 мс. Это отдельные измерения в текущем окружении, не гарантия скорости и не результат проверки на Windows. SVG, схемы, формы и матрица в этой проверке совпали с предыдущей версией; дополнительно был проверен один реальный проект из 45 действий. Работу мыши, визуальную плавность и сборку EXE необходимо проверить на целевом компьютере Windows.
