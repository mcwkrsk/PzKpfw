# Установщик, релизы и модули

## Что получает пользователь

Один файл `PzKpfw-Setup-<версия>.exe` (несколько мегабайт) со страницы Releases.

- Установка без прав администратора в `%LOCALAPPDATA%\Programs\PzKpfw`.
- Во время установки скачивается среда выполнения: Python 3.12 с Tk, python-docx и Pillow. Это около 27 МБ, после распаковки около 75 МБ. Контрольная сумма SHA-256 проверяется. Если рядом с установщиком лежит файл `PzKpfw-runtime-….zip` с правильной суммой, вместо скачивания используется он.
- Системный Python не используется и не изменяется.
- Ярлык в «Пуске», по желанию на рабочем столе. Связь с `.is2` — галочка «Открывать файлы .is2 в PzKpfw».
- Удаление через «Параметры → Приложения». По желанию удаляются и модули с настройками.
- При запуске программа раз в сутки проверяет новый релиз. Отключается в «Справка → Проверять обновления автоматически». При обновлении программа предлагает сохранить проект, скачивает установщик, проверяет его по `SHA256SUMS.txt`, закрывается, обновляется и запускается снова.
- Если среда выполнения не изменилась между версиями, обновление её не скачивает (сравнивается `runtime\pzkpfw-runtime.id`).

Расположение файлов:

| Что | Где |
|---|---|
| Программа и среда | `%LOCALAPPDATA%\Programs\PzKpfw\` (`app\`, `runtime\`, `pzkpfw.pyw`) |
| Модули | `%LOCALAPPDATA%\PzKpfw\modules\` |
| Данные модулей, журнал ошибок запуска | `%LOCALAPPDATA%\PzKpfw\module-data\`, `…\logs\last-error.txt` |
| Тема, язык | `%APPDATA%\PzKpfw\` (как и раньше) |

Запуск из исходников (`Запустить_PzKpfw.bat`) по-прежнему работает. Автообновление в такой копии не включается, команда «Проверить обновления» открывает страницу релизов.

## Как выпустить новую версию

1. Поменяйте номер в `src/is2_re/__init__.py`, например `__version__ = "9.10.1"`.
2. Сделайте коммит и запушьте его.
3. Поставьте тег с тем же номером и запушьте:
   ```
   git tag v9.10.1
   git push origin v9.10.1
   ```
4. GitHub Actions → «Release installer» сделает остальное:
   - соберёт среду и установщик;
   - прогонит тесты на собранной среде;
   - на Windows установит, запустит, переустановит и удалит программу;
   - опубликует релиз с файлами `PzKpfw-Setup-9.10.1.exe`, `PzKpfw-runtime-….zip` и `SHA256SUMS.txt`.

   Если тег не совпадает с `__version__`, сборка остановится.

**Не удаляйте из релизов `PzKpfw-runtime-….zip`.** Установщик этой версии скачивает среду по ссылке на свой релиз.

Пробная сборка без релиза: Actions → «Release installer» → Run workflow. Файлы появятся в артефакте `PzKpfw-installer` у запуска.

Тег с дефисом (`v9.11.0-beta`) публикуется как pre-release. Программа такие релизы не предлагает для автообновления.

Локальная сборка (Windows, нужен Inno Setup 6):

```
python installer/build_release.py --python-dir <папка standalone Python с python.exe и pythonw.exe>
```

Подходящую папку можно получить командой `uv python install cpython-3.12-windows-x86_64-none`.

## Модули

Модуль — ZIP-архив с `module.json` и Python-пакетом. Образец лежит в `modules/example`:

```
module.json
hello_example/__init__.py     # функция register(api)
```

`module.json`:

| Поле | Значение |
|---|---|
| `id` | латиница в нижнем регистре, цифры, `-`; уникален: `course-rules-stankin` |
| `name`, `description`, `author` | то, что видит пользователь в окне «Модули» |
| `version` | `1.0.0`; по нему определяются обновления |
| `min_app_version` | минимальная версия PzKpfw |
| `entry` | `пакет:функция`; имя пакета должно быть уникальным, не `json`, `docx` и т. п. |
| `requirements` | дополнительные библиотеки (`["httpx>=0.27"]`); ставятся в папку модуля из готовых wheel-пакетов |

Что модуль получает в `register(api)`:

- `api.add_menu_command(подпись, функция)` — пункт в меню «Модули»;
- `api.document()` — открытый `ProjectDocument` или `None`, только для чтения;
- `api.apply_change(сообщение, функция(doc))` — изменить проект одной правкой, которую можно отменить через Ctrl+Z;
- `api.show_text(заголовок, текст)` — окно с отчётом;
- `api.project_path()`, `api.data_dir` (своя папка для настроек), `api.app_version`, `api.tr()`.

Ошибка в модуле не закрывает редактор: она показывается в окне «Модули» и в сообщении. Установка, удаление и включение модуля действуют после перезапуска PzKpfw.

### Как опубликовать модуль

1. Упакуйте модуль:
   ```
   python tools/pack_module.py modules/example
   ```
   Появится `dist-modules/hello-example-1.0.0.zip`, а в консоли — готовая запись для каталога с `sha256` и `size`.
2. Загрузите ZIP в релиз. Можно в отдельный релиз этого репозитория с тегом `module-hello-example-1.0.0` (Releases → Draft a new release → перетащить ZIP → Publish). Можно в собственный репозиторий автора модуля.
3. Скопируйте ссылку на файл: правый щелчок по нему в релизе → «Копировать адрес ссылки». Вида `https://github.com/<владелец>/<репо>/releases/download/<тег>/<файл>.zip`.
4. Добавьте запись в `modules/index.json` в ветке `main` и укажите в поле `url` эту ссылку. Другие группы делают это через pull request: вы проверяете код модуля и сливаете PR.
5. Через минуту-другую модуль появится у всех в «Модули → Управление модулями…» (кнопка «Обновить список»).

**Новая версия модуля:** поднимите `version` в `module.json`, повторите шаги 1–4 и замените старую запись в каталоге. У пользователей в окне «Модули» появится «Доступна версия …».

Каталог устанавливает только ZIP с совпадающим SHA-256. Если файл в релизе подменят, установка откажет. Поэтому `sha256` в каталоге меняется только вместе с проверкой кода. Кнопка «Установить из файла…» нужна авторам для проверки модуля до публикации и предупреждает, что подлинность не проверена.

## Подпись кода (SignPath Foundation)

Без подписи Windows SmartScreen при первом запуске установщика показывает «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».

Бесплатный вариант для открытых проектов — SignPath Foundation (https://signpath.org). Сертификат выдаётся на фонд, поэтому в Windows издателем будет «SignPath Foundation», регистрировать компанию не нужно. Условия: лицензия OSI (GPL-3.0 подходит), публичный репозиторий, сборка только через GitHub Actions, двухфакторная защита GitHub и SignPath, хотя бы один уже выпущенный релиз, никакого закрытого кода в подписываемых файлах. Заявку рассматривают, одобрение не гарантировано.

Порядок: выпустить первый релиз этим workflow → подать заявку → после одобрения добавить шаг подписи в `.github/workflows/release.yml` (место отмечено комментарием) → в README добавить раздел «Code signing policy». Даже подписанный установщик первое время может вызывать предупреждение, пока у него нет репутации в SmartScreen.
