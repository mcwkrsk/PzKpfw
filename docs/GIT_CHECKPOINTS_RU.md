# Контрольные точки Git в PzKpfw

Во вкладке «Git» окна ассистента показываются текущая ветка, расхождение с upstream и изменённые файлы.

Контрольная точка создаётся только после нажатия пользователя и дополнительного подтверждения со списком файлов.
PzKpfw выполняет локальный commit и никогда не запускает `push`.

## Ограничения безопасности

- существующие подготовленные к commit изменения не смешиваются с контрольной точкой;
- включаются только файлы, явно показанные в окне;
- пути проверяются относительно корня репозитория;
- `.env`, ключи, сертификаты, учётные данные, журналы, временные файлы и резервные копии исключаются;
- при ошибке commit выбранные файлы снимаются с подготовки, рабочие файлы не изменяются;
- сообщение имеет вид `PzKpfw checkpoint: <краткое описание плана>`.

Если открытый `.is2` находится вне Git-репозитория, вкладка сообщает об этом и контрольная точка недоступна. Это не
мешает встроенной резервной копии проекта, которая создаётся отдельно перед применением плана ассистента.
