# План реализации ИИ-ассистента PzKpfw

> **Статус 12.11.2026:** реализованы безопасный протокол версии 1, атомарное применение на клоне, окно предпросмотра, построение схемы предметной задачи, методический индекс, пакет `is2_skill`, официальный вход через ChatGPT, локальные контрольные точки Git, OCR и экспорт черновика отчёта.

> **Граница курсовой:** обязательный результат — схема ИС-2, а не численный расчёт. Ассистент создаёт декомпозицию действий, формы А/Б/С/Д/Д1/Д2, символические параметры, потоки данных и ссылки на методику. Имеющийся вычислительный модуль оставлен как необязательная техническая проверка и выключен по умолчанию.

## 1. Цель

Добавить в PzKpfw ассистента, который по заданию на курсовой проект сможет:

1. определить состав предметной задачи;
2. предложить понятный план построения схемы;
3. подготовить изменения проекта `.is2`;
4. показать их пользователю до применения;
5. безопасно применить изменения;
6. проверить структуру, связи, обозначения формул и сериализацию проекта;
7. указать использованные методические материалы и места, требующие ручной проверки.

Главный принцип: модель не редактирует XML напрямую. Она формирует только разрешённые структурированные операции, а PzKpfw проверяет и выполняет их на копии документа.

## 2. Что уже есть и должно быть переиспользовано

В проекте уже существуют необходимые базовые механизмы:

- копирование документа через `ProjectDocument.clone()`;
- проверка проекта через `ProjectDocument.validate(deep=True)`;
- предварительная проверка сериализации через `serialization_preflight()`;
- операции добавления действий, параметров и объектов;
- перенумерация структуры курсового проекта;
- история изменений, отмена/повтор, резервные копии;
- сравнение документов.

Ассистент должен стать отдельным слоем над этими механизмами, а не дублировать их.

## 3. Границы первого рабочего варианта

Первый рабочий вариант, или MVP, должен поддерживать одну проектировочную и одну проверочную задачу.

В MVP входят:

- ручной ввод задания в структурированном виде;
- формирование и просмотр плана;
- ограниченный набор безопасных операций над `.is2`;
- выполнение операций на копии документа;
- просмотр различий до сохранения;
- валидация и откат при ошибке;
- ручная вставка JSON-ответа модели для отладки всей цепочки без авторизации во внешних сервисах.

В MVP не входят:

- OCR сканов;
- автоматическая авторизация ChatGPT или Claude;
- Git-ветки и коммиты из интерфейса;
- генерация полного отчёта курсовой;
- одновременная поддержка всех 30 тем;
- самостоятельное принятие ассистентом спорных инженерных решений.

## 4. Предлагаемая структура модулей

```text
src/is2_re/
  assistant/
    models.py          # задание, план, операция, результат
    schemas.py         # строгая проверка входного JSON
    operations.py      # реестр разрешённых операций
    executor.py        # применение на копии, проверки, откат
    context.py         # подготовка контекста проекта для модели
    prompts.py         # системные правила и шаблоны запросов
    providers/
      base.py          # общий интерфейс поставщика модели
      manual_json.py   # вставка/загрузка ответа вручную
      openai.py        # позднее
      anthropic.py     # позднее
  methodology/
    index.py           # темы, страницы и источники
    search.py          # поиск релевантного материала
  assistant_gui.py     # панель ассистента
```

Точные имена могут измениться после первого прототипа, но границы ответственности желательно сохранить.

Рекомендуемый объём первого спринта:

1. Создать пакет `assistant` и базовые модели данных.
2. Утвердить JSON-формат версии `1`.
3. Реализовать 4 операции: добавить объект, добавить действие, добавить параметр, изменить параметр.
4. Реализовать выполнение пакета на клоне документа.
5. Подключить глубокую валидацию и предварительную проверку сериализации.
6. Сформировать текстовое сравнение до/после.
7. Добавить ручную загрузку JSON без подключения модели.
8. Написать модульные тесты успешных и ошибочных сценариев.
9. Прогнать цикл: открыть `.is2` → применить операции → сохранить → снова открыть → проверить.
10. Подготовить маленькое окно предпросмотра или временный диалог подтверждения.

Результат спринта: PzKpfw безопасно принимает структурированный пакет изменений и применяет его только после успешной проверки. Само подключение ИИ на этом этапе ещё не требуется.

  "assumptions": [],

  "operations": [

Это только начальный контракт. Перед реализацией он должен быть согласован с реальной структурой `ProjectDocument` и покрыт тестами.

## 8. Общие критерии готовности

Функция считается готовой, если:

- есть успешный тест;
- есть тест отказа на неверных данных;
- ошибка не повреждает открытый проект;
- изменение отображается в предпросмотре;
- изменение можно отменить;
- проект проходит глубокую валидацию;
- проект сохраняется и повторно открывается без потери данных;
- инженерное утверждение имеет источник либо явно помечено как допущение;
- в журнал не попадают ключи доступа и лишние пользовательские данные.

## 9. Основные риски

- **Ошибочная формула или коэффициент.** Нужны ссылки на источник и ручное подтверждение.
- **Повреждение `.is2`.** Только операции через доменную модель, клон и атомарное применение.
- **Неверный OCR.** Формулы и числа всегда отмечаются для сверки со сканом.
- **Слишком большой первый релиз.** Сначала два контрольных сценария, затем расширение тем.
- **Зависимость от конкретной модели.** Общий интерфейс поставщика и единый проверяемый протокол.
- **Утечка данных.** Минимальный контекст, явный список отправляемых материалов и отсутствие секретов в журналах.

## 10. Ближайшее решение

Основное ядро и этапы 1–10 реализованы. Следующие осмысленные шаги:

1. Получить корректно заполненный преподавателем `.is2` и добавить сравнение с эталоном.
2. Провести живой контрольный прогон основного поставщика модели с пользовательским ключом, не сохраняя ключ в проекте или журнале.
3. Подключать второй облачный поставщик только после стабильного живого прогона первого.
4. Для реального OCR установить Tesseract; без него приложение продолжает безопасно формировать отчёты и сообщает, что распознавание недоступно.
